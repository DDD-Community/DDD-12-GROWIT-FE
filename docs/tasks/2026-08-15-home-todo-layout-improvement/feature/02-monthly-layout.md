# Task 02. 월간 투두 레이아웃 개선

> 프론트엔드 변경 계획: [월간 레이아웃 프론트엔드 문서](../frontend/02-monthly-layout.md)

## 목적

월간 캘린더에서 선택한 날짜의 투두 목록이 주간 및 상세 화면과 동일한 정책으로 정렬되도록 한다.
캘린더 전환이나 날짜 선택 후에도 정렬 결과가 안정적으로 유지되어야 한다.

## 현재 구조

- `TodoListContainer`에서 `calendarView === 'monthly'`이면 `TodoList`의 `list` 모드를 사용한다.
- 월간 캘린더 자체는 42개 날짜 셀과 카테고리별 개수 인디케이터를 렌더링한다.
- 날짜를 선택하면 해당 날짜의 투두를 조회하여 `ListView`에 전달한다.
- 기존 `groupAndSortTodos`는 목표 그룹 내부에서 완료 여부만 정렬한다.
- 시간 유무·시간 값·콘텐츠 가나다순에 대한 공통 정책이 없다.

## 구현 범위

### 1. 공통 정렬 함수 사용

월간 선택일의 모든 투두에 다음 정책을 적용한다.

1. 미완료 투두를 완료 투두보다 먼저 표시한다.
2. 같은 완료 상태에서는 시간이 있는 투두를 먼저 표시한다.
3. 시간이 있는 투두는 `HH:mm` 오름차순으로 표시한다.
4. 시간이 없는 투두는 콘텐츠 가나다순으로 표시한다.
5. 비교 결과가 같으면 안정적인 마지막 비교 기준을 사용한다.

목표별 그룹 UI를 유지하는 경우에도 각 목표 그룹 내부의 정렬 결과는 같은 정책을 따라야 한다.
그룹 자체의 가나다순 및 `미분류` 마지막 정책은 유지한다.

### 2. 상태 변경 후 재정렬

- 투두 완료 상태를 변경하면 서버 반영 및 쿼리 갱신 후 완료 투두 영역으로 이동한다.
- 투두의 시간이나 내용을 수정하면 갱신된 값으로 다시 정렬한다.
- 투두를 추가하면 선택한 날짜와 정렬 위치에 즉시 반영된다.
- 주간·월간 뷰를 전환해도 같은 날짜의 정렬 결과가 일관되어야 한다.

### 3. 월간 캘린더 회귀 방지

이번 작업은 선택일 투두 목록의 정렬을 대상으로 한다. 다음 기존 기능은 유지한다.

- 월 이동
- 날짜 선택
- 월간 캘린더 접기·펼치기 제스처
- 날짜별 카테고리 인디케이터
- 주간·월간 뷰 전환
- 선택 날짜 재클릭 동작

## 정렬 예시

입력:

```text
[완료] 운동하기 08:00
[미완료] 장보기 (시간 없음)
[미완료] 회의 13:00
[미완료] 아침 식사 08:00
[완료] 독서 (시간 없음)
```

기대 결과:

```text
[미완료] 아침 식사 08:00
[미완료] 회의 13:00
[미완료] 장보기 (시간 없음)
[완료] 운동하기 08:00
[완료] 독서 (시간 없음)
```

## 테스트 시나리오

1. 시간 있는 미완료 투두 여러 개
2. 시간 없는 미완료 투두 여러 개
3. 완료·미완료와 시간 유무가 모두 섞인 목록
4. 같은 시간 또는 같은 콘텐츠를 가진 투두
5. 목표별 그룹 및 `미분류` 그룹
6. 완료 토글 직후 목록 위치 변경
7. 투두 추가·수정·삭제 후 목록 갱신
8. 월 이동, 날짜 이동, 주간·월간 전환 후 정렬 유지

## 완료 조건

- [ ] 월간 선택일 목록에 공통 정렬 정책이 적용된다.
- [ ] 목표 그룹 내부에서도 동일한 정렬 정책이 적용된다.
- [ ] 기존 그룹 정렬과 `미분류` 마지막 정책이 유지된다.
- [ ] 완료·추가·수정 후 재조회된 목록이 올바르게 재정렬된다.
- [ ] 월간 캘린더의 이동·선택·제스처·인디케이터 동작에 회귀가 없다.
